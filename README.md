# 磁标读头脉冲串解码器（Magnetic-Stripe Pulse Decoder）

速度漂移会让同一串读头脉冲在不同时钟假设下得到不同解码。本工具对整数时钟
**τ = 80..120（微秒）逐一枚举**，并判定解码内容是否唯一。纯前端实现
（TypeScript + React + Vite + SVG），**所有计算只在浏览器中完成，无后端、无网络请求**。

## 输入格式

一个 **JSON 整数数组**，长度 **6..200**，每个元素为 **20..150 微秒的整数**，
表示读头输出的相邻脉冲间隔时长：

```json
[100, 50, 50, 100, 100, 96, 48, 48, ...]
```

- 输入非法（JSON 语法错误、不是数组、长度越界、元素不是 20..150 的整数）时，
  **错误按位置稳定汇总**：整份级错误排在最前，其余按数组下标升序；
  此时**整份拒绝并清除旧结果**，页面不保留任何此前的解码。
- 合法输入立即在本地解码，无需提交。

## 解码规则

对每个整数 τ ∈ [80, 120]：

1. **间隔分类**（间隔只能属于其一，兼属或皆不属则淘汰该 τ）：
   - 长型：`|d − τ| ≤ 6`
   - 短型：`|2d − τ| ≤ 6`
2. **成位**：
   - 一个长型间隔 → 位 `0`
   - 相邻两个短型间隔 → 位 `1`
   - 出现孤立短型（奇数连串）→ 淘汰该 τ
3. **分组**：位流每 5 位一组，前 4 位**低位在前**组成码值，
   第 5 位须使本组中 `1` 的总数为**奇数**（奇校验）。
4. **帧结构**：`起始码 11` + `1..12 个载荷码` + `结束码 15` + `LRC`
   - 载荷码值限 `0..9`
   - LRC 的前四位 = 此前所有码值**逐位异或**
   - 帧外不得有任何剩余位

## 判定与展示

枚举 41 个 τ 后，按解出的**数字串**（载荷码拼接）汇总：

| 情况 | 显示 | 展示内容 |
| --- | --- | --- |
| 没有任何 τ 有效 | `unreadable` | 提示信息 |
| 所有有效 τ 解出**同一个**数字串 | `decoded` | 数字串、全部有效 τ；按**最小 τ** 用 SVG 绘制间隔分类与成位（短型成对括号、5 位分组与码角色） |
| 有效 τ 解出**多个不同**数字串 | `ambiguous` | 按数字串**字典序**列出每个串及其成立的 τ |

页面底部的「τ 枚举明细」可展开查看每个 τ 的有效/淘汰原因。

## 连续漂移复核（普通裁决为 unreadable 后）

一次刷卡中读头时钟可能**持续缓慢变速**，固定 τ 无法成帧时，检修员可在
`unreadable` 面板填写**相邻间隔允许的整数时钟跳变量上限** `k`（0..40 微秒），
发起「连续漂移复核」：

- 为**每个原始间隔**选择一个 80..120 微秒的整数**局部时钟** τᵢ；
- 相邻局部时钟之差（含短型对内部的两个间隔）必须满足 `|τᵢ₊₁ − τᵢ| ≤ k`；
- 每项仍须共同满足既有规则：长短型互斥、短型两两成位、奇校验、
  起始码/结束码/载荷 0..9/帧外无残余/LRC——**不先切段，也不逐项独立判定**，
  全部约束在同一条逐间隔时钟轨迹上一次性成立。

求解在「间隔 × 局部时钟」网格上做有界跳跃动态规划，并枚举长型位/短型对的
铺法；在所有**完整见证**中按解出的数字串汇总：

| 情况 | 显示 |
| --- | --- |
| 无任何完整见证 | 明确为 `unreadable`（说明是结构失败还是跳变上限不足） |
| 只有一个数字串 | 展示内容、**逐间隔时钟轨迹**（SVG 折线 + 时钟点）与**每次跳变**明细表 |
| 多个数字串 | 按字典序列出各串及其规范轨迹、见证数 |

同一内容存在多条轨迹时，图示轨迹先取**总跳变量** Σ|τᵢ₊₁−τᵢ| **最小**、
再取**逐间隔时钟序列字典序最小**的一条。`k = 0` 时所有局部时钟相同，
复核结论与固定时钟裁决一致（有单元测试锁定）。

- 跳变上限非法（非整数或超出 0..40）时给出错误且不产出结论；
- **任何编辑**（脉冲输入或跳变上限）或非法跳变量都会**撤下旧漂移结论**，需重新发起；
- 原有输入、普通裁决（decoded / ambiguous / unreadable）、τ 枚举明细与图示保持可用。

> 与固定 τ 的情形同理：在当前参数下时长的可判长型/短型区间不相交，
> 分类结构至多一种，因此实践中复核结果同样只会是 `decoded` 或 `unreadable`；
> 多串的枚举与字典序汇总仍按规格保留（单测覆盖核心 DP、字典序 tie-break、
> 见证计数、上限单调性与 k=0 一致性）。

> 备注：在给定参数（τ ∈ 80..120、容差 6）下，某一时长 d 可能被判为长型的 τ 区间
> [d−6, d+6] 与可能被判为短型的 τ 区间 [2d−6, 2d+6] 不可能同时与 [80,120] 相交
> （要求 d 同时落入 [74,126] 与 [37,63]）。因此所有“有效 τ”的分类与成位必然一致，
> 实践中结果只会是 `decoded` 或 `unreadable`；`ambiguous` 的判定与展示仍严格按规格
> 实现（汇总逻辑有单元测试覆盖），以防参数调整后出现多解。

## 本地开发

```bash
npm install
npm run dev        # 开发服务器
npm test           # Vitest 单元测试
npm run build      # 类型检查 + 生产构建到 dist/
npm run e2e        # Playwright 端到端验收（自动 build + preview）
```

Node.js ≥ 20。首次运行 E2E 需安装浏览器：`npx playwright install chromium`。

## Docker Compose

```bash
# 启动 Web（宿主机端口可用 WEB_PORT 覆盖，默认 8080）
WEB_PORT=9000 docker compose up --build web
# 然后浏览器访问 http://localhost:9000

# 一次性验收服务：运行单元测试、生产构建与 Playwright E2E，结束后退出
docker compose up --build verify
```

- `web`：`nginx` 静态托管 `dist/`；容器内监听 80，宿主端口由
  `WEB_PORT`（默认 `8080`）覆盖。
- `verify`：一次性服务，退出码 0 表示全部验收通过。

## 目录结构

```
src/
  decode.ts        # 纯函数核心：校验、分类、成位、帧校验、τ 枚举与汇总
  drift.ts         # 连续漂移复核：铺法枚举 + 有界跳跃 DP（规范轨迹、见证计数）
  encode.ts        # 测试/示例用编码器（固定时钟与连续变速时钟）
  decode.test.ts   # 固定 τ 裁决的 Vitest 单元测试
  drift.test.ts    # 漂移复核的 Vitest 单元测试
  App.tsx          # 界面：输入、错误汇总、普通裁决、漂移复核发起与结论
  PulseDiagram.tsx # SVG：间隔分类 → 成位 → 5 位分组 → 逐间隔时钟轨迹/跳变
e2e/app.spec.ts    # Playwright 验收（含漂移复核发起、撤下、轨迹与跳变）
```
